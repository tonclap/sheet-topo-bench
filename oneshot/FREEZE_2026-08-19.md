## План экзамена — ровно два оценочных прогона-цепочки

Генерация корпусов (не вскрытие; после генерации — проверка бит-в-бит
вторым прогоном с тем же сидом, sha256 манифестов):

    python inject_errors.py --scroll PHercParis4 --grid-cache ../../output/figgrids \
        --cache ../../output/figcache --out ../../output/topo/corpus_paris4_h2 \
        --per-type 100 --seed 20260819
    python inject_errors.py --scroll PHerc0139 --grid-cache ../../output/figgrids \
        --cache ../../output/figcache --out ../../output/topo/corpus_0139_h2 \
        --per-type 100 --seed 20260819

Цепочка A2 (`--bands heldout`) и цепочка B2 (`--bands all`), каждая:
`detect_v1` (строка v1, чекпоинт `ckpt_<corpus>` ) → `detect_v2` (пулы,
чекпоинт `ckpt_<corpus>_v2`, гейт против отчёта detect_v1) → `probe_ct`
(ct-окна, чекпоинт) → `exam_v5lu.py` (гейты 1–2, строка v5lu) →
`baselines.py`. Затем `heldout_summary.py` дописывает секцию v2 в
`HELDOUT_RESULTS.md`. Возобновление с чекпоинтов после падения среды —
продолжение того же прогона (детерминизм посегментного расчёта, прецедент
v1-экзамена). После завершения обеих цепочек бюджет held-out v2
израсходован полностью.

ΔERL строк v2 публикуется точкой с контекстом §3 (оракул-потолок,
случайный пол из 10 сидов) из `erl_context` отчётов; сегментный джекнайф
(как `erl_jackknife.json` у v1) в экзамен не входит — при желании
добавляется позже офлайн-реплеем из чекпоинтов, числа экзамена не меняя.

## Врезка 2026-08-20: правка замороженного кода, не касающаяся чисел

По итогам код-ревью публикуемого пакета в 66 шиппед-скриптов добавлен
одинаковый гард из четырёх строк:

```python
for _stream in (sys.stdout, sys.stderr):
    if hasattr(_stream, 'reconfigure'):
        _stream.reconfigure(errors='replace')
```

**Зачем.** Записи прогонов печатают кириллицу, Δ и знак минуса. На консоли
Windows с кодовой страницей по умолчанию (cp1251/cp866) любой такой `print`
даёт `UnicodeEncodeError` и уносит с собой весь вывод скрипта. Проверено
до правки: `transfer_breakdown.py` и `ablation_summary_v5.py` — оба скрипта
README называет запускаемыми — падали ровно так. `verify.py` этот гард нёс
с самого начала, остальные — нет.

**Почему это не нарушает заморозку.** Гард меняет только кодировку потоков
вывода. Отчёты пишутся через `open(..., encoding='utf-8')` и его не видят;
ни одно вычисление к нему не обращается. Доказательство, а не рассуждение:
`verify.py` после правки заново порождает 12 сводок теми же скриптами и
сверяет их с отгруженными файлами — совпадение байт-в-байт, плюс 74
привязки чисел README. Вывод `transfer_breakdown.py` сверен диффом до и
после правки — идентичен.

**Что осталось незатронутым.** Правки, которые могли бы сдвинуть числа,
не внесены и вынесены в `UNTRIED.md` («Правки замороженного кода,
отложенные по правилу заморозки») с наблюдаемым условием взятия.
